}

    **Create `frontend/src/lib/components/UnifiedPlayer.svelte`:**

    Per user decision "Same `<video>` element for live and recorded — source switches seamlessly", this component owns ONE `<video>` element and switches source attachment internally based on `mode`. It absorbs the live MSE logic from `MsePlayer.svelte` and the HLS recording logic into a single component.

    Svelte 5 component with these props (using `$props()`):
    ```typescript
    interface Props {
        mode: 'live' | 'recording';
        wsUrl?: string;          // required when mode='live' — go2rtc WebSocket URL
        hlsSrc?: string;         // required when mode='recording' — HLS playlist URL
        playbackRate?: number;   // only meaningful in recording mode (default: 1)
        onTimeUpdate?: (time: Date | null) => void;
        onError?: (msg: string) => void;
        onReady?: () => void;
    }
    let { mode, wsUrl, hlsSrc, playbackRate = 1, onTimeUpdate, onError, onReady }: Props = $props();
    ```

    State:
    ```typescript
    let videoEl = $state<HTMLVideoElement | null>(null);
    let hlsInstance = $state<Hls | null>(null);
    let status = $state<'connecting' | 'loading' | 'ready' | 'playing' | 'error'>('loading');
    let errorMsg = $state('');
    ```

    Import: `import Hls from 'hls.js';`

    **Cleanup helper** — call before each mode switch to tear down the current source:
    ```typescript
    function detachCurrentSource() {
        // Tear down HLS if active
        if (hlsInstance) {
            hlsInstance.destroy();
            hlsInstance = null;
        }
        // Clear video source (also cleans up any MSE object URL)
        if (videoEl) {
            videoEl.pause();
            videoEl.removeAttribute('src');
            videoEl.load(); // reset the element
        }
    }
    ```

    **Primary $effect** — reacts to `mode`, `wsUrl`, `hlsSrc`, and `videoEl`. This is the core source-switching logic:

    1. If `!videoEl`, return early
    2. Call `detachCurrentSource()` to clean up previous attachment
    3. **If `mode === 'live'` and `wsUrl`:**
       - Set `status = 'connecting'`
       - Create `MediaSource`, create object URL, set `videoEl.src = objectUrl`
       - On `sourceopen`: open WebSocket to `wsUrl` with `binaryType = 'arraybuffer'`
       - Handle first text message as codec info JSON (same as MsePlayer.svelte):
         - Parse JSON, extract `codecs` or `type` field
         - `addSourceBuffer` with `video/mp4; codecs="${codecs}"`, mode `'segments'`
         - Queue-based append pattern with `updateend` listener (copy from MsePlayer.svelte)
       - Handle binary messages: push to queue, call appendNext
       - On first binary data appended, call `videoEl.play()`, set `status = 'playing'`, call `onReady?.()`
       - Handle `ws.onerror`: set `status = 'error'`, `errorMsg = 'WebSocket connection failed'`, call `onError?.(...)`
       - Handle `ws.onclose`: if still connecting, set error status
       - Return cleanup: `() => { ws?.close(); URL.revokeObjectURL(objectUrl); }`

    4. **Else if `mode === 'recording'` and `hlsSrc`:**
       - Set `status = 'loading'`
       - If `Hls.isSupported()`:
         - Create `new Hls({ maxBufferLength: 30, maxMaxBufferLength: 60 })`
         - `instance.loadSource(hlsSrc)`, `instance.attachMedia(videoEl)`
         - On `Hls.Events.MANIFEST_PARSED`: set `status = 'ready'`, call `onReady?.()`
         - On `Hls.Events.ERROR`: if `data.fatal`, set error state, call `onError?.(data.details)`. If network error, try `instance.startLoad()` once.
         - Store: `hlsInstance = instance`
         - Return cleanup: `() => { instance.destroy(); hlsInstance = null; }`
       - Else if `videoEl.canPlayType('application/vnd.apple.mpegurl')`:
         - Set `videoEl.src = hlsSrc` (Safari native HLS)
         - Listen `loadedmetadata`: set `status = 'ready'`, call `onReady?.()`
         - Listen `error`: set `status = 'error'`, call `onError?.('Playback failed')`

    **Effect for playbackRate** (`$effect` reacting to `playbackRate` and `videoEl`):
    - If `videoEl && mode === 'recording'`, set `videoEl.playbackRate = playbackRate`

    **Template** — single video element with status overlays:
    ```svelte
    <div class="relative aspect-video w-full overflow-hidden rounded-lg bg-black">
        <!-- svelte-ignore a11y_media_has_caption -->
        <video
            bind:this={videoEl}
            autoplay
            muted
            playsinline
            class="h-full w-full object-contain"
            ontimeupdate={() => {
                if (onTimeUpdate && mode === 'recording') {
                    onTimeUpdate(hlsInstance?.playingDate ?? null);
                }
            }}
            onplay={() => { status = 'playing'; }}
        ></video>
        {#if status === 'connecting'}
            <div class="absolute inset-0 flex items-center justify-center">
                <p class="text-sm text-gray-400">Connecting to live stream...</p>
            </div>
        {:else if status === 'loading'}
            <div class="absolute inset-0 flex items-center justify-center bg-black/50">
                <svg class="h-8 w-8 animate-spin text-gray-400" viewBox="0 0 24 24" fill="none">
                    <circle cx="12" cy="12" r="10" stroke="currentColor" stroke-width="4" class="opacity-25"></circle>
                    <path fill="currentColor" d="M4 12a8 8 0 018-8V0C5.373 0 0 5.373 0 12h4z" class="opacity-75"></path>
                </svg>
            </div>
        {:else if status === 'error'}
            <div class="absolute inset-0 flex items-center justify-center">
                <p class="text-sm text-red-400">{errorMsg || 'Playback failed — try refreshing the page'}</p>
            </div>
        {/if}
    </div>
    ```

    **IMPORTANT:** The MSE WebSocket logic (queue, appendNext, sourceopen, codec detection) must be copied faithfully from the existing `MsePlayer.svelte` — read it first. The key difference is that this lives inside a mode-conditional branch of the same `$effect`, not in a separate component.
