# Phase 4 — UI Design Contract

> Visual and interaction contract for the Playback & Timeline frontend. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |

## Spacing Scale

Declared values (Tailwind default 4px base unit, matching existing codebase):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (`gap-1`, `p-1`) |
| sm | 8px | Compact element spacing, badge padding (`gap-2`, `py-2`) |
| md | 16px | Button padding, control bar gaps, card padding, section content (`gap-4`, `px-4`, `p-4`) |
| lg | 24px | Main panel/content area padding, section breaks (`p-6`, `space-y-6`, `gap-6`) |

Exceptions:
- Timeline track height: 48px (touch-friendly scrub target, 12 Tailwind units)
- Playback controls bar height: 48px (consistent with timeline track)
- Speed preset buttons: 36px min-width (9 Tailwind units) for comfortable tap targets

## Visual Hierarchy

**Focal point:** `<video>` element — largest element on the page, horizontally centered, high-contrast `bg-black` against the `bg-gray-950` page background. All controls and navigation sit below the video in a top-to-bottom reading order: video → controls → timeline → date/zoom navigation.

## Component Inventory

### HlsPlayer.svelte
Reusable HLS.js player shell wrapping a `<video>` element.

| Prop | Type | Description |
|------|------|-------------|
| `src` | `string` | HLS playlist URL (`.m3u8`) |
| `playbackRate` | `number` | Speed multiplier (default: 1) |
| `onTimeUpdate` | `(time: Date \| null) => void` | Wall-clock time callback via `hls.playingDate` |
| `onError` | `(msg: string) => void` | Playback error callback |
| `onReady` | `() => void` | Player ready after manifest parsed |

States: `loading` → `ready` → `playing` | `error`

Video element classes: `h-full w-full object-contain` (matches MsePlayer.svelte).

Safari fallback: If `Hls.isSupported()` is false but `video.canPlayType('application/vnd.apple.mpegurl')` is true, set `video.src` directly.

### PlaybackControls.svelte
Horizontal control bar below the video.

| Element | Spec |
|---------|------|
| Play/pause button | 24×24px SVG icon, `text-gray-300 hover:text-white` |
| Current time display | `text-sm font-mono text-white` — format: `HH:MM:SS` |
| Duration display | `text-sm font-mono text-gray-500` — shows window end time |
| Separator | `text-gray-600` — literal " / " between current and duration |
| Speed selector | Row of pill buttons: `0.5×`, `1×`, `2×`, `4×`, `8×` |
| Speed button (active) | `rounded-md bg-blue-600 px-2 py-1 text-xs text-white` |
| Speed button (inactive) | `rounded-md bg-gray-800 px-2 py-1 text-xs text-gray-400 hover:text-white hover:bg-gray-700` |
| "Go Live" button | Visible only during recording playback; `rounded-md bg-red-500 px-4 py-1 text-xs text-white hover:bg-red-600` |

### Timeline.svelte
Zoomable horizontal timeline bar with recording availability visualization.

| Element | Spec |
|---------|------|
| Track background | `h-12 rounded bg-gray-800` |
| Recording segment fill | `bg-green-500` rectangles positioned absolutely within track |
| Gap regions | No fill — track background shows through as `bg-gray-800` |
| Playhead | 2px wide white vertical line (`bg-white`) with 8px wide transparent hit area |
| Hover indicator | 1px wide gray vertical line (`bg-gray-500`) following mouse position |
| Hover tooltip | `absolute -top-8 rounded bg-gray-900 px-2 py-1 text-xs text-gray-300 shadow-lg border border-gray-700` — shows timestamp at cursor position |
| Time axis labels | `text-xs text-gray-500` spaced evenly below the track |
| Zoom interaction | Mouse wheel / trackpad pinch to zoom, drag to pan |
| Click interaction | Click positions playhead, triggers playlist refetch centered on that time |

Zoom presets (rendered as pill buttons below timeline):

| Preset | Label | Window |
|--------|-------|--------|
| 1h | "1h" | 1 hour visible |
| 6h | "6h" | 6 hours visible |
| 24h | "24h" | 24 hours visible |
| 7d | "7d" | 7 days visible |

Zoom button styling: same pattern as speed buttons (active = `bg-blue-600`, inactive = `bg-gray-800`).

### DatePicker (navigation)
Native `<input type="datetime-local">` for jumping to a specific date/time.

| Spec | Value |
|------|-------|
| Element | `<input type="datetime-local">` |
| Styling | `rounded-lg border border-gray-700 bg-gray-800 px-4 py-2 text-sm text-gray-100 focus:border-blue-500 focus:outline-none focus:ring-1 focus:ring-blue-500` |
| Behavior | On change, centers timeline on selected date/time and loads playlist |

Source: RESEARCH.md recommends native `<input type="datetime-local">` over custom calendar widget.

## Interaction States

### Live ↔ Recording Transition

| State | Video Source | Controls | Timeline |
|-------|-------------|----------|----------|
| **Live** | go2rtc MSE WebSocket | Play/pause disabled; speed buttons hidden; LIVE badge pulsing | Playhead pinned to "now" (right edge), timeline auto-scrolls |
| **Recording** | HLS.js `.m3u8` playlist | Play/pause enabled; speed buttons visible; "Go Live" button visible | Playhead follows current playback time, user can scrub |
| **Transitioning** | — | Controls disabled, spinner overlay on video | Timeline frozen |

Transition trigger:
- **Live → Recording**: User clicks any point on the timeline that is in the past
- **Recording → Live**: User clicks "Go Live" button, or scrubs playhead to current time (within 10 seconds of now)

### Timeline Zoom Levels

| Zoom Level | Segment Rendering | Labels |
|------------|-------------------|--------|
| 1h view | Individual segments visible as distinct green bars | Every 5 minutes |
| 6h view | Segments merge into contiguous green bands | Every 30 minutes |
| 24h view | Availability shown as solid green bands per hour | Every 2 hours |
| 7d view | Daily availability summary (green bar per day with coverage) | Day labels |

### Loading States

| State | Visual |
|-------|--------|
| Page loading | `text-gray-400` "Loading playback..." with spinning SVG (matches statistics page pattern) |
| Playlist loading | Translucent overlay on video with small spinner (`bg-black/50` over video) |
| Timeline data loading | Skeleton pulse on timeline track (`animate-pulse bg-gray-700`) |
| Switching source | Brief spinner overlay on video, controls disabled |

### Error States

| Error | Visual | Recovery |
|-------|--------|----------|
| HLS playback failure | Red text overlay on video: "Playback failed — try refreshing" | Auto-retry once after 3 seconds, then show error |
| Segment not found | Skip to next segment; if persistent, show "Some segments unavailable" toast | Non-blocking — playback continues |
| No recordings in range | Timeline shows empty track (all gray-800); no error state, just empty | User selects different date |
| Network error | Video overlay: "Connection lost — reconnecting..." | Auto-retry with exponential backoff |

## Accessibility Notes

- Video element must include `playsinline` attribute (matches MsePlayer.svelte)
- Speed buttons use visible text labels (not icon-only)
- Timeline hover tooltip uses `aria-live="polite"` for screen reader updates
- Play/pause button includes `aria-label` ("Play" / "Pause")
- Color alone never indicates state — green fill is supplemented by position on timeline axis
- Focus ring on all interactive elements: `focus:ring-1 focus:ring-blue-500 focus:outline-none` (existing pattern)
